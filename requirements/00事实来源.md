# 00 · 事实来源表（内容可信度清单）

> `requirements/` 是**建站前的内容准备工作区**：把素材先准备在这里，再让 AI 照着产页。
> 本文件是两张准备表之一——**每个页面的关键事实从哪来**。另一张是 [00对标参考.md](00对标参考.md)（对标站拆解）。
>
> 选词决定后（见 [docs/sourcing.md](../docs/sourcing.md)）、写内容前，先填这张表。

## 为什么要有这张表

- **内容可信度直接关系 E-E-A-T 和排名**：Google 评估 Experience（真实经验）的第一步，就是你的事实有没有出处。一条编造的兑换码/Boss 数值，毁掉的是整站信任。
- 这是模板内容规则的硬要求：AI **绝不编造游戏数据**（见 [AGENTS.md](../AGENTS.md)「Conversational Content Authoring」与 [docs/content-format.md](../docs/content-format.md)）。这张表就是给 AI 的"数据口粮"——表里没有的事实，AI 只能标「待补充」。
- 顺手把来源链接和时间整理下来，后续**内容保鲜**（codes 更新、数值改动）时直接回访来源，不用重新找。

## 怎么生成（推荐让 AI 跑）

把你的页面矩阵（打算做哪些页，如 codes / 3 篇 boss 攻略 / tier list）连同下面的提示词发给支持联网调研的 AI（ZCode / Claude Code / Codex 等）：

```text
根据下面的页面矩阵联网调研，生成「事实来源表」。
【页面矩阵】
<粘贴你的页面清单，每行：页面 slug / 类型 / 目标关键词>
【任务】
1. 对每个页面列出关键事实（兑换码及有效期、Boss 数值/弱点、掉落率、版本号等），逐条标注：来源链接 + 来源最后更新时间
2. 来源优先级：游戏官方（官网/官方社媒/更新日志）> 权威 wiki（Fandom 等）> 高播放攻略视频字幕
3. 同时分析 2-3 个竞品 wiki 网站对同一事实的写法，标注分歧点（哪家的数据互相矛盾）
4. 对检索不到可靠来源的事实，明确标「无来源，需玩家实测/用户提供」，禁止推测
5. 输出为 Markdown 表格，按页面分组
只调研和整理，不写任何文章。
```

**实测提示：来源里加上「YouTube 视频字幕内容」和「竞品网站分析」两条，产出的事实表会明显更丰富**——视频字幕里有大量官方页面不会写的实操细节（打法、触发条件、坑）。

## 模板（复制下面这段，按页填）

```markdown
## {页面 slug}（{类型}，目标词：{keyword}）

| 关键事实 | 来源链接 | 来源最后更新 | 备注 |
| --- | --- | --- | --- |
| 兑换码 SPRING2026，有效期至 4/30 | 官方 Discord #announcements | 2026-04-02 | 竞品 wiki 均未收录，首发优势 |
| Boss 二阶段弱点火，伤害加成 ×2 | 官方 patch notes v1.4 | 2026-03-28 | 与 Fandom 记载（×1.5）冲突，以 patch notes 为准 |
| 掉落率 12%（传说难度） | YouTube 某视频字幕（30 次实测） | 2026-04-05 | 样本小，正文标注"社区实测" |
| （检索不到）复活币获取上限 | — | — | 无来源，标「待补充」问用户 |
```

## 使用规则

- 每条事实**必须有来源链接 + 时间**；检索不到的写「待补充」，别让 AI 硬编。
- 来源冲突时按优先级取（官方 > 权威 wiki > 视频实测），并把冲突写进备注——正文里可以大方写"官方 patch notes 为 X，社区实测为 Y"，这反而是可信度加分项。
- codes 类页面：来源时间是**新鲜度凭证**，配合模板的 7 天保鲜规则（`pnpm refresh-audit`）定期回访来源更新。
